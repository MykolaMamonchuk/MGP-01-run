## Як переміряти

```bash
godot res://tools/perf/perf.tscn                  # рівень 1, вікно
PERF_LEVEL=8 godot res://tools/perf/perf.tscn     # інший рівень
godot --headless res://tools/perf/perf.tscn       # лише CPU (draw calls = 0)
```

Замірник ([tools/perf/perf.gd](../../tools/perf/perf.gd)) сам вимикає vsync і стелю fps,
стартує рівень, чекає 5 с і усереднює 900 кадрів. Звіт — у консоль і в `user://perf.txt`.

**Чи не зіпсувалася картинка** — [tools/shots/shots.gd](../../tools/shots/shots.gd): знімає
п'ять сцен (лужок на 3 і 7 доріжок, ліс під час «перебудови кубиками», ліс, море) і друкує
статистику декору.

```bash
SHOT_TAG=before godot --path <worktree-зі-старим-комітом> --fixed-fps 60 res://tools/shots/shots.tscn
SHOT_TAG=after  godot --fixed-fps 60 res://tools/shots/shots.tscn
```

`--fixed-fps 60` обов'язковий: без нього швидша збірка встигає інше число кроків і кадри
розходяться самі по собі. Якщо правка не міняла порядок звертань до випадковості, кадри мають
збігтися **попіксельно**; якщо міняла — порівнюємо очима, а збіг розподілу перевіряємо за
надрукованою статистикою.

**Правила чесного заміру:**

- **Vsync має бути вимкнений.** Інакше `frame_ms` буде рівно 16.67 — це стеля монітора, а не гра.
- **Три прогони мінімум.** Перешкоди й декор спавняться випадково, тож `Track` гуляє
  на ±20 мешів між запусками. Одиничний прогін нічого не доводить.
- **Час кадру з десктопа на телефон не переноситься.** Переносяться структурні числа:
  draw calls, кількість вузлів і мешів, трикутники. Їх і порівнюємо між заходами.
- Перед/після правки міряємо на **тому самому рівні** — рівні дуже різні за щільністю.
