# Як Luanti робить туман і воду — з їхнього коду, а не з припущень

Luanti (колишній Minetest) — єдина з наших контрольних ігор із відкритим кодом, тож тут не
здогади з кадрів, а те, що написали автори. Джерело: `github.com/luanti-org/luanti`,
`client/shaders/`. Заміряно на тому самому Redmi 8A: **59 к/с, drawtime 6,2–12 мс**
(див. `2026-09-24-luanti.md` — там числа й застереження про те, що замір знято під землею).

## 1. Головне: усе дороге вимкнено ЗА ЗАМОВЧУВАННЯМ

З `builtin/settingtypes.txt`:

| налаштування | типове |
|---|---|
| `enable_waving_water` — хвиля на воді | **false** |
| `enable_water_reflections` — відблиски на воді | **false** |
| `enable_dynamic_shadows` | **false** |
| `enable_bloom` | **false** |
| `enable_auto_exposure` | **false** |

Тобто ті 60 к/с — це вода без хвилі й без відблисків, світ без тіней і без свічення.
Порівнювати наші «усе ввімкнено» з їхніми 60 к/с було б нечесно; порівнювати треба
з нашим станом «Плавно», де ми теж усе це погасили.

**І це не перемикач у рантаймі.** Код цих ефектів стоїть за `#if`, тобто компілюється
окремий варіант шейдера. У фрагментному шейдері вузлів 43 директиви умовної компіляції, у
вершинному — 28. Вимкнений ефект не має ціни взагалі: його немає в скомпільованій програмі.

## 2. Вода: окремого шейдера НЕМАЄ

Вода в Luanti малюється тим самим `nodes_shader`, що й каміння, земля й дерево. Її колір —
звичайна вибірка з текстури:

```glsl
vec4 base = texture2D(baseTexture, uv).rgba;
```

Жодної процедурної математики в пікселі. Уся «водяність» — у самій картинці текстури.

Коли хвилю вмикають, вона у **ВЕРШИННОМУ** етапі й лише там:

```glsl
vec3 wavePos = wpos.xyz + cameraOffset;
wavePos.x /= WATER_WAVE_LENGTH * 3.0;
wavePos.z /= WATER_WAVE_LENGTH * 2.0;
wavePos.z += animationTimer * WATER_WAVE_SPEED * 10.0;
pos.y += (snoise(wavePos) - 1.0) * WATER_WAVE_HEIGHT * 5.0;
```

Порівняння з тим, що було в нас: наш `water.gdshader` рахував **75 викликів `_circ` на
кожен піксель** плюс `_fbm`, і це коштувало 112 мс на пляжі. Ми прийшли до того самого
результату, що й вони, але іншим шляхом — запекли візерунок у текстуру. Різниця в тому, що
в нас текстура тепер ДАЄ той самий візерунок, а в них візерунок із самого початку був
намальований, а не порахований.

## 3. Туман: п'ять операцій на піксель

```glsl
float clarity = clamp(fogShadingParameter
    - fogShadingParameter * length(eyeVec) / fogDistance, 0.0, 1.0);
float fogColorMax = max(max(fogColor.r, fogColor.g), fogColor.b);
if (fogColorMax < 0.0000001) fogColorMax = 1.0;
col = mix(fogColor * pow(fogColor / fogColorMax, vec4(2.0 * clarity)), col, clarity);
```

Лінійний за відстанню, без повітряної перспективи, без кривої глибини, без впливу на небо.
Поруч авторський коментар про обхід драйверного бага: «туман малюється правильно, лише якщо
остання операція перед `clamp()` — додавання; інакше `clamp()`, схоже, ігнорується».

Наш `Environment.fog` у Godot коштував 17 мс, і жодна його властивість не важила — дорогий
був увесь шлях. Ми замінили його вісьмома прозорими завісами (0,7 мс). Luanti робить те
саме дешево інакше: у них туман теж на піксель, але це п'ять операцій, а не повний шлях
загального призначення.

## 4. Що з цього випливає для нас

| вони | ми (після правок) |
|---|---|
| дороге вимкнено й НЕ СКОМПІЛЬОВАНО | дороге вимкнено станом якості, шейдер міняється |
| вода — текстура | вода — запечена текстура візерунка |
| хвиля у вершинах, за прапорцем компіляції | хвиля у вершинах, коштує нуль |
| туман — 5 операцій | туман — 8 прозорих завіс |
| дальність огляду 70 м | дальність не різали (кандидат) |
| субдискретизація 1 (повна роздільність) | повна роздільність |

**Найбільша структурна різниця — умовна компіляція.** У них вимкнений ефект зникає з
програми; у нас `Quality` міняє шейдер або властивість, тобто ми платимо за перемикач, а не
за код. Для нас це поки не вузьке місце, але якщо доведеться робити ще кілька варіантів
матеріалів, їхній підхід (окремий шейдер під профіль, а не гілка в одному) — правильний
взірець. Ми вже пішли ним для води: `water.gdshader` / `water_cheap` / `water_unlit` /
`water_opaque` — це чотири окремі програми, а не один шейдер із прапорцями.
