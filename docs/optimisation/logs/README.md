# Журнали замірів

Машинні дані для аналітики. Формат TSV, по рядку на кожну **сходинку масштабу рендера**
кожного варіанта — тобто один варіант дає п'ять рядків (0.45 / 0.60 / 0.75 / 0.90 / 1.00).

## Стовпці

| стовпець | що це |
|---|---|
| `варіант` | назва кроку серії |
| `масштаб` | сходинка масштабу рендера, у сотих (45 = 0.45, 100 = 1.0) |
| `мед_мс`, `p95_мс`, `мін_мс` | час кадру за годинником |
| `кс` | кадрів на секунду з медіани |
| `виклики`, `примітиви`, `обєкти` | лічильники рендера в кадрі |
| `відео_мб`, `текстури_мб`, `буфери_мб` | відеопам'ять |
| `цп_рендера_мс` | `viewport_get_measured_render_time_cpu` |
| `пам_статична_мб` | статична пам'ять процесу |
| `обєктів_усього`, `вузлів`, `ресурсів`, `безхазяйних` | лічильники рушія |
| `фіз_процес_мс`, `процес_мс` | час фізики й `_process` |

**`цп_рендера_мс` — єдиний часомір, що працює.** Часомір GPU
(`viewport_get_measured_render_time_gpu`) повертає нулі в усіх бекендах, куди ми маємо
доступ, тому його в журналі немає.

## Як читати

**Порівнювати варіанти можна лише по всіх сходинках разом**, а не по одній: час кадру на
Android квантований кроком 16,67 мс, і одне число на фіксованому масштабі бреше. Див.
`docs/MEMORY.md`.

Рядки `К1`…`К4` — контролі, повтор першого варіанта. Їхній розкид показує дрейф від
нагрівання: якщо він більший за міряну різницю, прогін непридатний.
