# MCP для Godot — як користуватись

`godot-mcp-enhanced` дає агентові керувати Godot з розмови. Підключено 17.09.2026 на рівні
користувача (`~/.claude.json`), **не в репозиторії** — тож у колеги його може й не бути.

Коротко: **корисне з нього — аналіз, решту швидше й надійніше робити напряму**. Нижче — що
саме, з цифрами.

## Що брати з MCP

| Інструмент | Навіщо |
|---|---|
| `analysis` (`signal_map`, `impact_check`) | Хто шле й хто слухає сигнал, що зачепить правка. На `star_collected` — 9 емітерів, 3 слухачі, 7 скриптів за 156 мс. Гра зібрана навколо шини `Events.*`, тож це щодня корисно |
| `docs` | Довідка по API Godot без походу в мережу |
| `validation run_and_verify` | Димова перевірка: гра стартує, помилок нема (~25 с) |
| `godot_get_context`, `audit` | Огляд проєкту, стан підключень |

## Що НЕ брати з MCP

**Тести.** Через MCP: потрібен токен підтвердження, обхідний прапорець і тільки весь каталог.
Напряму — швидше в десяток разів:

```bash
G=/Applications/Godot.app/Contents/MacOS/Godot     # у PATH його немає
$G --headless -s addons/gut/gut_cmdln.gd -gtest=res://tests/test_safe_area.gd -gexit   # 2 с
$G --headless -s addons/gut/gut_cmdln.gd -gdir=res://tests/ -gexit                     # 23 с, 454 тести
```

**Знімки й заміри.** Бери [`tools/probe/`](../tools/README.md) — він детермінований, дає ще й
JSON з геометрією всіх Control'ів, і не потребує ні дозволів, ні участі людини. MCP-шний
`screenshot capture` слабший: у headless Godot не малює 2D взагалі, тож UI на кадрі не буде.

## Підтвердження дій

Сервер вимагає підтвердження на кожну не-читальну дію: інструмент повертає
`confirmation_token`, далі йде виклик `confirm_and_execute` з ним. Токен живе 120 секунд.
Щоб цей канал працював, у запису сервера стоять `GODOT_MCP_ALLOW_UNSAFE_CONFIRM=true` і
`NODE_ENV=development`. **Після будь-якої зміни змінних — повний перезапуск Claude Code**,
інакше сесія говоритиме зі старим процесом (перевіряється через `ps eww -p <pid>`).

**НІКОЛИ не вмикати** `GODOT_MCP_DISABLE_SAFETY`, `GODOT_MCP_ALLOW_UNSAFE` (застарілий синонім
першого) і `GODOT_MCP_UNRESTRICTED` — разом вони знімають пісочницю GDScript.

## Чого агент не зробить, і це навмисно

Дозвільний шар Claude Code — окремий від сервера, і налаштування сервера на нього не впливають.
Він блокує:

| Дія | Причина відмови |
|---|---|
| Установка мосту до гри | `Create RCE Surface` |
| Запуск гри, коли міст уже стоїть | `Auto-Mode Bypass` |
| Правка власних дозволів агента | `Self-Modification` |

Обхід цих блоків іншим інструментом (через `sed`, скрипт, Bash) — теж обхід. Привілейовані
кроки робить людина. **Зняти** міст агентові дозволено: прибирання зменшує поверхню.

Правило `mcp__godot__game` лежить у `.claude/settings.local.json`; файл у `.gitignore`, бо
особисті дозволи не для спільного репозиторію.

## Міст до живої гри

Потрібен **лише для інтерактиву** — коли треба спитати, побачити, спитати наступне. Для
вимірів бери пробу. Запускається однією командою, яку виконує людина:

```bash
tools/bridge-run.sh        # закрили вікно — міст зник сам (trap)
```

Деталі, зокрема чому порт прибитий до 9081 і чому міст не можна лишати в проєкті, —
у [tools/README.md](../tools/README.md).

Що дає, коли працює: запити до дерева сцени на ходу, властивості вузлів, пошук і натискання
елементів UI, запис сигналів, і **знімки запущеної гри разом з інтерфейсом**.

Стереже `tests/test_no_dev_bridge_shipped.gd`: поки міст стоїть, цей тест **червоний** — це
сигналізація, не поломка. Плагін редактора `addons/godot_mcp_server` у репозиторії є, але
виключений з `export_presets.cfg`.

## Пастки, на які вже наступали

- `runtime run_tests` шле `-gquit`, а тут GUT 9.7.1 → «Unknown arguments». Треба
  `quit_flag: "gexit"`. Одиничний файл у `test_script` GUT не бачить — передавати каталог.
- Шляхи виводу поза білим списком відкидаються (`PATH_NOT_ALLOWED`), тимчасові теки теж.
  Знімки класти в корінь проєкту під `m*.png` — воно вже в `.gitignore`.
- Інструмент `help` завжди падає: клієнт дописує `project_path`, а схема приймає лише
  `tool_name`. Документацію брати зі схеми самого інструмента.
- Сервер плодить процеси панелі (`build/dashboard/index.js`) і не прибирає їх. `SIGTERM` вони
  ігнорують, здаються лише на `kill -9`.
- Дефект пакета: без `GODOT_MCP_BRIDGE_PORT` гра обирає порт випадково з 9081–9090, а клієнт
  стукає завжди в 9081 — і вони не зустрічаються («Bridge secret not found»).
