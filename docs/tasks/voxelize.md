# Завдання: лисеня з Meshy у вокселі (tools/voxelize.py)

Для локальної сесії Claude Code на Mac (тут є термінал, Godot і сама модель).
Мета: перетворити `docs/refs/models/fox.glb` на воксельні частини героя **lys** (Лиско),
вставити їх у `data/heroes.json`, переконатись, що тести й гра живі, і зробити знімок.

Усі команди — з кореня `games/mgp-01-run`.

## Що змінилось у прогоні v2

Перший прогін (`--pitch 0.075`) дав голову-кубик без морди й без хвоста, бо частини
підганялись під **фіксовану кількість вокселів** (6×5×8 тощо). Тепер:

- контракт із Hero3D — **у метрах** із допуском в один воксель, кількість вокселів вільна;
- **`--pitch` типово 0,04 м** (голова ≈ 11 шарів замість 6) — деталі моделі виживають;
- `--fit` масштабує частину в метрах і тягне x/z за точною віссю (пропорції не пливуть),
  ширина тиснеться до 0,58 м, вухо до 0,22 м, хвіст — рівно до `TAIL_LEN` 0,35 м;
- хвіст шукається не лише **позаду** тулуба, а й **піднятий над крупом** (лисеня тримає його
  вгору) — `--tail-z` лишився як ручний запобіжник;
- морда, носик і очні западини розмічаються **частками голови** (передні 40 % глибини,
  нижні 55 % висоти; очі 2×2 на 60–75 % висоти, ±25 % по x), а не двома-трьома вокселями.

```

```

Має бути `усі тести пройшли`. Якщо ні — далі не йди, це баг інструмента, а не моделі.

## 1. Подивитись, що вийде (нічого не пишемо)

```bash
python3 tools/voxelize.py docs/refs/models/fox.glb --hero lys --height 0.98 --pitch 0.04 --dry-run
```

У виводі дивись на три речі:

1. `[i] перед моделі: …` — має бути повернуто **в -Z** (морда лисеняти дивиться на камеру).
2. `[i] шия на y = N, лапки: BL, BR, FL, FR, поріг вуха L, задня площина тулуба z = Z` —
   лапок має бути чотири. Якщо далі буде `[!] хвоста не видно`, візьми `z` зі зрізів
   (перший ряд хвоста `a`) і задай `--tail-z <z>`.
3. ASCII-зрізи: рядок = z (перший рядок — перед), колонка = x, шари згори вниз.
   Літери: `h` голова · `e`/`E` вуха · `t` тулуб · `a` хвіст · `1` FL · `2` FR · `3` BL · `4` BR.

Голова має бути зверху-спереду, хвіст — знизу-ззаду, чотири лапки — по кутах нижніх шарів.
Якщо картинка не така — див. «Що робити, коли негарно» нижче. **Не йди далі, поки зрізи не читаються.**

---

## 2. Згенерувати частини й .vox

```bash
python3 tools/voxelize.py docs/refs/models/fox.glb --hero lys --height 0.98 --pitch 0.04 \
    --out data/voxels --vox docs/refs/models/out/
```

Отримаєш:

- `data/voxels/hero_body_lys_ai.json`
- `data/voxels/hero_head_lys_ai.json`
- `data/voxels/hero_leg_lys_ai.json` (передня ліва лапка — шаблон для всіх чотирьох)
- `data/voxels/hero_ear_lys_ai.json` (одне вухо; друге Hero3D дзеркалить сам)
- `data/voxels/hero_tail_lys_ai.json`
- `docs/refs/models/out/lys_ai.vox` — уся модель для MagicaVoxel (можна підправити руками)

Рядки `[!]` — попередження про габарити з `tests/test_heroes_v15.gd`. За замовчуванням
увімкнено підгін `--fit`, і він тримає габарити **в метрах** із допуском в один воксель:
тулуб 0,375 м, голова 0,45 × 0,45 м (висота × глибина), лапка 0,225 м, вухо ≤ 0,22 м,
хвіст 0,35 м. Тож попереджень бути не має. `--no-fit` лишає як є — тоді тести впадуть.
У рядках `[+]` тепер друкуються і вокселі, і метри — звір їх із цими числами.

Наприкінці інструмент друкує готовий блок `"parts": {...}` — **heroes.json він не чіпає**.

---

## 3. Вставити в heroes.json

У `data/heroes.json`, героєві `"lys"`, заміни рядок `"parts": {...}` на надрукований блок:

```json
"parts": {"body": "hero_body_lys_ai", "head": "hero_head_lys_ai", "leg": "hero_leg_lys_ai",
          "tail": "hero_tail_lys_ai", "ear": "hero_ear_lys_ai"},
```

Якщо якась частина не згенерувалась (інструмент написав `[!] частина '…' порожня`) —
лиши для неї стару назву (`hero_tail_fox`, `hero_ear_fox` тощо).

## 4. Тести

```bash
godot --headless -s addons/gut/gut_cmdln.gd -gconfig=tests/.gutconfig.json -gexit
```

Найважливіше — `tests/test_heroes_v15.gd`: він звіряє габарити частин **у метрах** із
константами Hero3D і **допуском в один воксель самої частини** (лапка 0,225 м, голова
0,45 м заввишки і 2 × `HEAD_HALF_D` = 0,45 м завглибшки, тулуб 0,375 м, згенерований хвіст
`TAIL_LEN` 0,35 м, згенероване вухо ≤ 0,22 м), ширину < 0,6 м і те, що всі символи
палітри — з набору `o d c k i t m`. Якщо щось червоне — поверни старі назви в `heroes.json`
і напиши в звіті, що саме впало.

## 5. Гра й знімок

```bash
godot .
```

Меню → лисеня стоїть у каруселі героїв. Перевір очима:

- морда дивиться **на камеру**, а не в спину й не вбік;
- лапки на місцях, на бігу махають; вуха обидва вгорі;
- **хвіст видно ззаду** й він не тоне в тулубі (Hero3D зсуває згенерований хвіст на пів
  `TAIL_LEN`, тож у JSON має бути рівно 0,35 м завглибшки);
- голова **не суцільний кубик**: видно виступ морди, кремовий перед, темний носик,
  темні очні западини під очима Hero3D;
- кольори **насичені**, не вицвілі (це вже полагоджено в `_setup_sky`: `adjustment_saturation`
  1.15, контраст 1.05, блум 0.18 / поріг 1.1, амбієнт 0.55 при сонці 1.1).

Знімок лисеняти в меню поклади у **`docs/refs/have/fox_ai.png`** (порівняй із
`docs/refs/want/characters/*-1.jpg`).

## Готовий воксельний GLB (`--exact`)

`docs/refs/models/fox_voxel.glb` — це **вже воксельна** модель: зовнішній інструмент
перетворив `fox.glb` на кубики на рівній сітці. Її не треба воксeлізувати ще раз
(сітка «попливе», кольори загубляться) — для неї є режим `--exact`, який сітку **знаходить**.

### 1. Подивитись

```bash
python3 tools/voxelize.py docs/refs/models/fox_voxel.glb --exact --name fox_voxel \
    --height 0.98 --out data/voxels --vox docs/refs/models/out/ --dry-run
```

У виводі дивись на:

1. `[i] розмір кубика (мода довжин ребер): 0.0XXX м` і `[i] габарит у кубиках: N×M×K` —
   якщо кубиків підозріло мало або тисячі, задай `--cube-size` вручну.
2. `[i] вокселів: снап граней N, trimesh.voxelize M` — числа мають бути близькі;
   інструмент друкує, який варіант узяв (`--grid faces|trimesh|auto`).
3. `[i] джерело кольорів: …` — `vertex_colors`, `текстура (UV центроїда грані)`,
   `матеріал (…)` або `нема (сірий)`.
4. `[i] кольорів: N після округлення -> 16 у палітрі` і самі зрізи: рядок = z (перший — перед),
   колонка = x, символи — кольори з палітри, надрукованої в кінці.

**Якщо модель без кольорів** — усе стане сірим `#B0B0B0` (у зрізах один символ `a`).
Тоді або перезаливай модель із vertex colors / текстурою, або (для героя) генеруй
з `--parts hero --zones`: кольори намалює Hero3D за палітрою героя.

### 2. Записати

```bash
python3 tools/voxelize.py docs/refs/models/fox_voxel.glb --exact --name fox_voxel \
    --height 0.98 --out data/voxels --vox docs/refs/models/out/
```

Отримаєш `data/voxels/fox_voxel.json` (уся модель одним вокселем) і
`docs/refs/models/out/fox_voxel.vox` зі **справжніми** кольорами.

### 3. Подивитись у грі

Найшвидше — не чіпаючи `data/heroes.json`:

```bash
godot res://src/debug/voxel_preview.tscn                    # типово fox_voxel
VOXEL=fox_voxel godot res://src/debug/voxel_preview.tscn    # будь-яке ім'я з data/voxels
```

`src/debug/voxel_preview.gd` — крихітна debug-сцена (камера + сонце + повільний оберт),
у грі не використовується. Esc — вийти. Якщо файлу нема, VoxelBuilder покаже рожевий кубик.

### 4. Якщо треба саме герой, а не ціла модель

```bash
python3 tools/voxelize.py docs/refs/models/fox_voxel.glb --exact --parts hero \
    --name fox_voxel --hero lys --height 0.98 --out data/voxels --vox docs/refs/models/out/
```

Сегментація та сама (лапки → голова + вуха → хвіст → тулуб), але **без `--fit`**: частини
лишаються зі справжньою кількістю вокселів, і інструмент лише **звітує**, чи збігаються їхні
висоти з константами Hero3D (`збігається` / `НЕ збігається — tests/test_heroes_v15.gd впаде`).
Кольори лишаються справжніми; щоб їх замінили кольори героя (символи `o d c k i t`),
додай `--zones`. `.vox` у будь-якому разі зі справжніми кольорами.

Якщо звіт каже «НЕ збігається» — або підбери інший `--height` (щоб знайдений кубик ліг у
метри Hero3D), або лиши цю модель як цілий воксель (`--parts none`) для декору чи прев'ю,
а героя генеруй звичайним режимом із `fox.glb` і `--fit`.

## Що робити, коли негарно

| Симптом | Причина | Ліки |
|---|---|---|
| Модель лежить на боці / зріст по Z | експорт Z-up не розпізнався | інструмент сам пише `[i] бачу Z-up`; якщо ні — переекспортуй Y-up |
| Герой дивиться назад або вбік | евристика «переду» помилилась (є `[!] перед визначено ненадійно`) | `--front +z` / `--front -z` / `--front +x` / `--front -x` |
| Лапок 2–3 замість 4 | лапки злиплись при грубій сітці | `--pitch 0.035`, або `--min-leg 2`, щоб відкинути дрібні плями |
| Голова захопила спину | шия визначена низько | `--neck N` (індекс y зі зрізів) або `--head-depth 11` (у вокселях!) |
| Вуха не знайшлись | вони нижчі за поріг | `--ear-lift 2` (у вокселях; 0 — авто, 0,10 м) |
| Хвоста нема | він не виступає за тулуб і не піднятий над крупом | `--tail-z N` — індекс z, з якого починається хвіст: бери його з рядка `переріз тулуба по z`, який інструмент друкує разом із `[!] хвоста не видно`, або зі зрізів `--dry-run` (перший ряд із `a`). Далі — `--tail-frac 0.2`, `--tail-step 0.75`; у крайньому разі лиши `hero_tail_fox` |
| Спина світла, живіт темний | у нас `d` — це низ; у hero_body.json — верх | `--dark-top` |
| Частина завелика/замала | вимкнено підгін | не став `--no-fit` |
| Голова знову «кубик» без морди | сітка завелика | `--pitch 0.04` (типово) або `0.035`; на 0,075 деталей просто нема |
| Забагато дрібних деталей, рябить | сітка надто дрібна | `--pitch 0.05`–`0.06` (менше вокселів — читабельніше для 3–7 років) |
| `--exact`: «не бачу регулярної сітки» | модель не воксельна або ребра нерівні | прибери `--exact` (звичайний режим) або задай `--cube-size` |
| `--exact`: кубиків удвічі більше/менше, ніж на око | мода зловила діагональ або пів-кубик | `--cube-size <м>` зі значення, яке видно в `[i] габарит у кубиках` |
| `--exact`: модель дірява | снап граней не побачив внутрішні кубики | `--grid trimesh` |
| `--exact`: усе сіре | у моделі нема vertex colors / текстури | перезаливай модель із кольорами або став `--parts hero --zones` |
| `--exact`: модель лежить на боці | автовизначення Z-up помилилось на довгому звірятку | `--up y` |

Правки руками: відкрий `docs/refs/models/out/lys_ai.vox` у MagicaVoxel, підправ, потім

```bash
python3 tools/vox2json.py docs/refs/models/out/lys_ai.vox --name hero_head_lys_ai \
    --size 0.04 --palette tools/palette_hero.json
```

(`tools/palette_hero.json` уже лежить у репо: `{"o": "#F08A3C", "d": "#BB6C2F", "c": "#F6E3C2",
"k": "#4A2C2A", "i": "#F04F86", "t": "#F6E3C2", "m": "#A8612A"}`; кожен колір .vox лягає
на найближчий символ). Без `--palette` символи роздаються автоматично за частотою.
