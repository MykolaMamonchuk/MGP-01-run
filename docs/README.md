`CHANGELOG`, `TASKS`, `EXPORT`, `MCP` — **живі** документи: один файл, який постійно правиться.
Усе інше — **серії**: тематична підпапка, а в ній датовані файли-зрізи.

## Конвенція для серій (optimisation, review, …)

**Один захід = один файл.** Ім'я: `РРРР-ММ-ДД-коротка-назва.md`
(наприклад `2026-09-07-render-budget.md`). Заходи не переписуємо один поверх одного —
так видно, що змінилося між замірами й хто що вже полагодив.

**Кожна знахідка — пункт чеклиста зі своїм ID:**

```markdown
- [ ] **OPT-03** · 🟡 середній · Пагорби й хмарки — 38 окремих мешів
  **Замір:** 14 сфер + 8 × 3 кубики, статичні відносно камери.
  **Що робити:** MultiMesh або один зшитий меш.
  **Очікуємо:** −35 draw calls.
  **Статус:** відкрито
```

ID незмінний назавжди: `OPT-nn` для оптимізації, `ARCH-nn` для рев'ю архітектури,
`BUG-nn` для помилок. На нього посилаються коміти й наступні заходи.

**Галочку ставимо у файлі, де знахідку знайшли** — саме так документ відповідає
на питання «чи виправлено». Разом із галочкою дописуємо рядок:

```markdown
  **Статус:** ✅ виправлено 2026-09-14, коміт `a1b2c3d`
```

Позначки статусу: `відкрито` · `в роботі` · `✅ виправлено` · `⏸ відкладено → Jira MGPP1-nn`
· `❌ не робимо (причина)`.

**Новий захід не копіює старі пункти.** Він міряє наново, а вгорі має рядок
«що з попереднього заходу закрилося». Якщо стару знахідку так і не полагодили —
на неї просто посилаються за ID, не дублюючи.

**Кожна підпапка має свій `README.md`** — індекс заходів, цільові бюджети
й інструкція, як повторити заміри.

## Подивитись на всі моделі гри одразу

    python3 tools/prop_sheet.py --out docs/refs/prop_sheet.png --cols 7 --cell 230

Один аркуш з усіма `assets/props/*.glb`: однаковий ракурс, під кожною — назва, трикутники й
розмір файлу. Модель понад стелю обводиться червоним. Порівняння «до/після» для окремих
моделей лежать поруч: `docs/refs/bush/`, `docs/refs/props_slim/`, `docs/refs/incoming/`.
